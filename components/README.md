# UI онбординга

`event-onboarding.tsx` — четыре шага с общим состоянием формы. `onboarding-assistant.tsx` — необязательные подсказки и быстрые ответы; внешнего LLM нет. При скрытии панели, смене шага и перезагрузке выбор сохраняется. Если storage недоступен, UI продолжает работать в памяти. После перезагрузки результата открываются детали: свежую доступность следует запросить заново.

Помощник показан только при заполнении формы; на мобильном экране следует после основного содержимого и не отодвигает форму вниз. На результатах его нет. Четыре демо-кнопки покрывают популярную и редкую категории, отсутствие подходящих кандидатов и отсутствие категории в городе.

Города, форматы, категории и языки загружаются из `/api/catalog`. Все результаты и объяснения приходят из `/api/match`; сравнение — из `/api/compare`. На клиенте нет копии CSV, ранжирования или вычисления доступности. Пустые ответы — нормальные состояния интерфейса. Запросы отменяются при изменении условий; таймаут 10 секунд, ошибки и повтор доступны без помощника.

`match-results.tsx` показывает цену и объяснение сразу, а совпавшие факты — внутри нативного `details` «Все условия профиля». Общая оговорка о цене и подтверждении доступности вынесена под карточки. Заголовок страницы соответствует исходу, включая отсутствие категории и дату вне календаря.

`suggestions` остаётся текстовым списком. Кнопки берутся из `suggestionActions?: SuggestionAction[]` общего контракта, а не из разбора текста: `changes` содержит конкретную дату, бюджет или город. Нажатие применяет одно изменение к запросу текущей выдачи и запускает серверный подбор; на время запроса кнопки отключены. Сервер повторно валидирует весь запрос. Предложение другого города означает проверку, а не обещание подходящего результата.

Пожелание обрабатывает серверная лексическая эвристика с нормализацией «е/ё» и ограниченным распознаванием отрицаний. Интерфейс не должен обещать полное понимание свободного текста или показывать процент пригодности.

Проверки: обычные `npm test`, `npm run typecheck`, `npm run build`, `npm run test:e2e`. Дополнительные регрессии нового UI: `npx playwright test --config components/playwright.config.ts`. Они покрывают синхронизацию диалога и карточек, отсутствие самопроизвольной отправки при переходе к деталям, сохранение полей, точный JSON запроса, отказ browser storage и повтор загрузки каталога. После установки Playwright требуется `npx playwright install chromium`.

`assets/cities.png` — иллюстративный диптих Алматы / Астана, созданный imagegen для этого интерфейса, не документальная фотография. Изображение входит в сборку через статический импорт и не требует внешнего сервиса. UI находится в `app/` и `components/`; API и контракт сохранены.

`event-controls.tsx` использует React DayPicker 9 (русская локаль, окно календаря датасета, сериализация даты без UTC-сдвига) и Radix Slider (клавиатура, мышь, касание). Ползунок меняет бюджет с шагом 10 000 ₸; поле принимает точную сумму и расширяет шкалу для больших бюджетов. Для библиотек обновлены `package.json` и `package-lock.json`. Выбор ответа в помощнике сразу переключает шаг; кнопки истории позволяют исправить город или формат.
