## 4. Что сказал Jev (все батареи в обоих порядках, контроли проверены)

**Как писать объяснения** (контроли ок):
| подход | требования | демо |
|---|---|---|
| код отбирает факты → LLM t=0 пишет → кэш, без ключа шаблон | 0.79 / 0.87 | 0.62 / 0.71 |
| только шаблон из фактов | 0.78 / 0.85 | 0.59 / 0.78 |
| гибрид с цитатой из описания | 0.41 / 0.36 | 0.52 / 0.41 |
| LLM сама пишет по профилю | 0.22 / 0.29 | 0.33 / 0.38 |

Вывод: факты считает код, LLM только формулирует. LLM «от себя» — худший вариант.

**Что поднимает в топ-3** (контроли ок после переделки): смысл описания 0.74 / 0.81 > формат 0.63 / 0.68 > бюджет 0.55 / 0.57 > язык 0.47 / 0.50 > часы 0.38 / 0.40 > настоящий профиль 0.34 / 0.25.

**Что даёт баллы жюри:** «почему не попали» 0.85 / 0.88 > три исхода 0.78 / 0.77 > панель пайплайна 0.77 / 0.78 > смысл описания 0.62 / 0.65 > сравнение дат, метки синтетики, подсказка ослабить ~0.45-0.49 > казахский интерфейс 0.09.

**Что ТЗ требует прямо** (абсолютный режим, зеркало): три исхода да 0.91; сравнение двух дат да 0.81 (зеркало 1.19, спорно, но в DoD это прямо написано — делаем); причины отсева при неполном результате 0.65/0.47 (спорно; в ТЗ «сказать, почему меньше» — делаем); личная причина каждого отсеянного — нет 0.11; эмбеддинги — нет; казахский UI — нет.

**Где я не согласен с Jev / где он ошибся:**
- В первой батарее «обязательно для проверки» Jev поставил фильтр занятости ниже «почему не попали». Это неверно: фильтр — п.3 ТЗ. Контроль был плохо поставлен, батарею про ранжирование я переделал.
- «Причины отсева» Jev считает спорными, но текст ТЗ требует их. Верю тексту.
- «Смысл описания» на первом месте, но во входе ТЗ нет поля «пожелание». Используем как: совпадение описания с типом события (свадебный фотограф на свадьбу) + опциональное поле пожелания.

## 5. Продукт: что строим

**Вход:** город, дата, тип мероприятия, категория, бюджет; опционально часы, язык, пожелание (свободный текст).

**Пайплайн (детерминированный):**
1. `candidates = city ∧ category`. Пусто → **исход «нет категории в городе»** + где она есть («в Алматы 3 флориста»).
2. Фильтры по очереди со счётчиками: занят на дату → формат → бюджет (`price_from ≤ budget`) → часы (`max_hours ≥ hours`, null = проходит) → язык.
3. Прошло 0 → **исход «есть, но не проходят»**: «из 8 банкетных залов: 5 заняты 14.11, 2 дороже бюджета, 1 не берёт той» + ближайший вариант, что изменить (дата / бюджет +X).
4. Прошло 1-2 → карточки + «почему меньше трёх» теми же счётчиками.
5. Ранжирование: смысл описания к типу события/пожеланию → запас по бюджету → язык → часы → настоящий профиль → `id` как тай-брейк. Без случайности.
6. Объяснение: код собирает факты, в т.ч. **контрастный факт** — чем карточка отличается от двух других (единственный на казахском, самый дешёвый, 12 ч против 6). LLM t=0 пишет 1-2 предложения только из этих фактов; ответ кэшируется по хешу запроса. Нет ключа или ошибка → шаблон из тех же фактов.

**Карточка:** имя, категория, город, цена, метка «синтетика» / «цена оценочная», «совпало 5 из 5», объяснение.

**Панель пайплайна:** 66 → 12 (город+категория) → 7 (свободны) → 5 (формат) → 3 (бюджет). Закрывает «команда объясняет пайплайн».

**Режим сравнения дат:** тот же запрос на вторую дату рядом, подсвечено, кто выпал из-за занятости.

**Вне объёма:** бронирование, авторизация, красивый UI, казахский интерфейс, дообучение, база данных.

## 6. Стек

Next.js (App Router, TypeScript), данные — JSON из CSV в репо, логика в `lib/` без фреймворка, API `POST /api/match`, тесты Vitest. OpenAI через `OPENAI_API_KEY` из `.env`, без ключа всё работает на шаблонах. Деплой на Vercel — бонус, не обязателен.

Почему не Python: один язык, одна команда запуска, UI и API в одном проекте.

## 7. Контракт между двумя людьми (зафиксировать первым)

```ts
// POST /api/match
type MatchRequest = {
  city: string; date: string /* YYYY-MM-DD */; eventType: string;
  category: string; budget: number; hours?: number; language?: string; wish?: string;
};
type Outcome = "matched" | "partial" | "no_category_in_city" | "none_pass" | "date_out_of_range";
type MatchResponse = {
  outcome: Outcome;
  message: string;                 // человеческий текст исхода
  cards: Card[];                   // 0..3
  funnel: { step: string; left: number; dropped: { reason: string; count: number }[] }[];
  suggestions: string[];           // «сдвиньте на 15.11 — свободны 2», «бюджет +100 000 — ещё 1»
};
type Card = {
  id: string; name: string; categories: string[]; city: string; priceFrom: number;
  synthetic: boolean; priceImputed: boolean;
  matched: string[]; total: number; // «совпало 5 из 5»
  explanation: string; explanationSource: "llm" | "template";
};
```
