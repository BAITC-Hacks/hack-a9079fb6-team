## Продукт

Из каталога 66 профилей выбрать до трёх доступных подрядчиков. Результат должен объяснять соответствие запросу и отличия показанных профилей, а при пустой выдаче — ограничения. Источник требований: [ТЗ](task.md). Правила допуска и оценки: [проверка положения](rules-verification.md).

## Архитектура

### Техническая доводка, 23.09, после 16:06

Пользователь уточнил приоритет: качество объяснений → честные редкие/занятые/пустые исходы → скорость → UI. Шесть требований ТЗ остаются неизменными. Миллион строк — конкретная нагрузочная проверка, не обещание работы с неограниченным объёмом.

Принято: потоково читать CSV один раз при старте процесса; опубликовать полностью проверенный неизменяемый снимок с индексами по городу/категории и ID. Один снимок используется для валидации и обеих дат сравнения. Результаты, исходы и последовательные счётчики отсева сохраняются. Выбирать top-3 за один проход, вычислять лексическую релевантность один раз на профиль; подсказки считать без полной сортировки и многократных проходов по датам. Изменение CSV применяется после перезапуска. Холодную загрузку, память и тёплый запрос измерять отдельно; при выходе за RAM понадобится постоянное индексированное хранилище.

Проверка: регрессии шести требований, сравнение старого и нового алгоритмов, реальный большой CSV со сведениями об оборудовании и ограничениях измерений. UI на этом этапе не меняется.

Next.js App Router + TypeScript; Vitest, Playwright. CSV читается локально через csv-parse. Без БД, аккаунтов, API-ключей и сетевых запросов к моделям. JSON-копия датасета не нужна: CSV — единственный источник истины.

1. Zod проверяет JSON, типы, календарную дату, ограничения длины и значения из каталога.
2. Код фильтрует город+категорию, занятость, формат, бюджет, часы и язык. Каждый профиль учитывается в первом исключившем его шаге; счётчики не суммируют пересекающиеся причины.
3. Сортировка: лексическое совпадение описания с типом/пожеланием, стартовая цена по возрастанию (запас бюджета), совпадение запрошенного языка, максимальная длительность, ID. Null длительности не означает ноль и проходит фильтр часов. Синтетичность не понижает качество.
4. Объяснения — точные значения, контраст среди показанных карточек и цитата описания с указанием источника. Это шаблоны, не генеративная модель. Одинаковые данные/запрос → одинаковый порядок и текст.
5. Альтернативы пересчитываются с сохранением всех прочих ограничений: ближайшая дата с большим числом кандидатов и минимальное увеличение бюджета.
6. Сравнение дат различает фактическую занятость и выход из top3 из-за изменения ранжирования.

## Контракты и состояния

Единственный исполняемый контракт: [lib/contract.ts](../lib/contract.ts). Описание HTTP: [contract.md](contract.md). `matched`/`partial` — успешный подбор, `no_category_in_city`/`none_pass` — два разных пустых исхода, `date_out_of_range` — ограничение календаря. Невалидный ввод возвращает HTTP400, не ложный пустой подбор.
